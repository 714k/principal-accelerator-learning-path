## HTML semantics

Use HTML elements for their meaning, not only their presentation. Keep a single
page-level `h1`, then use `h2` through `h6` in order for nested sections; do
not choose heading tags solely for visual size. Use `p` for paragraphs, `ul`
or `ol` for genuine lists, `table` for tabular relationships, and the native
semantic element that matches the content before adding CSS or ARIA.

## Concept cards

Render every concept and definition using the shared concept-card pattern. When
an explanatory paragraph immediately follows a concept card, keep that paragraph
inside the preceding card rather than rendering it as detached body text.

## Study success criteria

Render every item under “Criterios de éxito de la sesión” and “End-of-session
success criteria” as a reversible checkbox with a stable study identifier.

## Session content and presentation

- The table of contents is the session structure. Render it once as the TOC; do not repeat it as a numbered “Estructura de la sesión” section in the article.
- In the TOC, let ordered-list markers supply top-level section numbers. Do not repeat those numbers in link labels. Keep a subtopic number in its link label when its nested TOC list uses bullets and therefore supplies no number.
- Number visible structural H2 section labels sequentially from “SECCIÓN 1” / “SECTION 1”; introductory components such as estimated time, synthesis, objective, and preview do not count as sections. Keep TOC links and their ID-based destinations unchanged when renumbering section labels.
- On desktop session routes, keep the sidenav collapse button outside the expanded `<aside>`; position it just outside the rail when expanded and centered in the icon rail when collapsed. Preserve focus order, `aria-controls`, and synchronized `aria-expanded`; hide it on mobile.
- Render every “Síntesis en 30 segundos” / “Synthesis in 30 seconds” as an ordered list of individual cards, with two-digit accent-colored numbers beside the text, matching the visual reference supplied by the learner. Preserve the native `<ol>`/`<li>` semantics.
- On mobile, normalize every instructional ordinal pattern across all session routes—not only the main synthesis—including `.synthesis-plain`, `.synthesis`, `.canonical-ordered-list`, `.canonical-unordered-list`, generic instructional ordered lists, `.mechanism-steps`, `.reading-steps`, `.studio-flow`, `.s003-item`, simulator trace steps and numbered `<li>` elements containing a direct Q&A disclosure. Put the ordinal on its own full-width row above the text, use a large accent number, then render the text underneath with `padding-inline-start: 20px` from the card's inner edge; keep at least 16px of separation wherever desktop still places number and text side by side. Use normal block flow on mobile so anonymous text nodes mixed with `<strong>`, `<code>` or links never form accidental grid columns. Exclude the TOC, references and checkboxes, which have their own patterns.
- Keep the “Conceptos” / “Concepts” section itself unboxed. Render each concept, its definition, and its example together inside the shared concept card, matching PA-S002.
- Keep all structural session sections, including nested subtopics, on the page canvas without outer cards. Reserve cards for inner concepts and examples, widgets, and other intentional content blocks.
- Check long prose, URLs, code, and mixed inline content at desktop and mobile widths. Use `minmax(0, 1fr)`, `min-width: 0`, and safe wrapping or an appropriate horizontal scroller so text never gets clipped or squeezed into narrow columns.
- On mobile, tables retain their full intrinsic column width and scroll horizontally in a dedicated focusable container; never squeeze tables to the viewport or split words inside cells. Keep keyboard focus visible.
- Generate responsive variants from Mermaid sources: preserve the authored desktop direction and, for horizontal `flowchart`/`graph` sources with `LR` or `RL` direction, generate a mobile SVG from the same source with `TB` direction, selected with `<picture>`/`<source media>`. Preserve node order, labels, relationships and arrow direction. Keep embedded PA-S001 flows vertical on mobile; never rotate a whole SVG or clip nodes.
- Do not make an ordered-list `<li>` a CSS grid when its content has unwrapped text mixed with inline elements such as `<strong>` or `<code>`; anonymous text nodes become separate grid columns. Use normal block flow with a positioned number, or wrap all flow content in one block before using columns.
