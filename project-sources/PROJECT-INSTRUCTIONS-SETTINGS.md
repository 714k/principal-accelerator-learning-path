## Academic theory
Theory must be rigorous, source-backed, precise and easy to understand. Curate authoritative sources first: standards/BoKs, peer-reviewed work, books, institutional reports, official specs/docs, reputable case studies; blogs/community/marketing are supplementary.

Definitions, mechanisms and normative/non-obvious claims must be sourced. Distinguish facts/definitions, synthesis, examples, recommendations, hypotheses and measured evidence. Never cite ChatGPT/Codex as theory authority.

## Concept-first content
Every Main Topic/theoretical Subtopic starts: definition/scope/distinctions → mechanism/model → integrated discussion → examples/counterexamples → trade-offs/production implications. Use varied semantic structures: prose, subheadings, meaningful lists, numbered mechanisms, tables, diagrams, concise code/contracts, examples, misconceptions/failures and semantic callouts. Avoid walls of text, shallow bullet-only teaching and card soup.

## Complete Theory Phase
Every theory-bearing session completes before checkpoint/Design/Build/Codex/assessment: Session header/Objective → Learning Preview → Concepts → Main Topic → Subtopics → Theory → Practice Map → Time Breakdown → Real-World Example → Production-Ready Example → Visual Learning Studio → Exercises → Curated Sources and References → Resources → Knowledge Mastery Checklist → End-of-Session Success Criteria → Bridge. Then stop for study/discussion.

## Canonical UI Reference
`/ui-reference/` is canonical UI/UX reference for `site/`. Inspect it before creating/regenerating pages and derive look/feel, hierarchy, interaction and content-presentation patterns. It governs presentation, not theory truth/architecture. Accessibility, responsive, ES/EN, SVG, Technology Radar and accepted ADRs take precedence.

## Visual Learning Studio
Every theory session publishes an adaptive Studio derived from sourced theory. Mandatory: Mermaid mind map covering every Concept + Main Topic + theoretical Subtopic as responsive accessible SVG; flashcards covering the same sections with source links, front question, back answer+explanation, flip, keyboard, prev/next, counter, no-JS fallback and reduced motion. Add analogies/comparisons/maps/flows/sequences/timelines/decision matrices/failure propagation/pipelines/code walkthroughs/distinction/recall only when supported. No fixed global tab set.

## Dashboard + interactive study tracking
`site/` home (`/es/`, `/en/`) is a real mobile-first learning dashboard from PA-S001, not a hero/index-only landing page. Show available roadmap/session progress, checklist/exercise study tracking, evidence-backed mastery separately, artifacts, revisits, projects/systems and activity/next work using appropriate cards/tables/charts or honest empty states.

Trackable Exercises and Knowledge Mastery Checklist items use stable machine IDs shared by ES/EN and enabled controls that can be checked/unchecked and persisted. `disabled` checkboxes do not satisfy tracking. Checked items are study state only: never derive L1–L5, Completed or invented percentages from them.

## Navigation + responsive
Desktop global nav uses its column for phase-grouped sessions, projects/systems and primary destinations. Put page TOC below it or above article; avoid a wasteful second permanent rail. Priority: phone → tablet/iPad → desktop. No page-level horizontal overflow.

## Content conventions
On every published page expand every acronym/initialism at least once as `Full Term (ACRONYM)` or localized equivalent. Default Accelerator UIs avoid decorative pink, purple and rainbow palettes unless product/domain/brand requires them; prefer restrained neutrals plus accessible blue/cyan-teal/green/amber-orange/red accents. Color never carries meaning alone.

Mermaid is source; `site/` publishes responsive SVG with valid `viewBox`, content-width scaling, proportional `height:auto`, no required pan/zoom and no viewport overflow.

## Build / Codex
Only after Theory: Design → Build → Prove → Think → Publish. Codex inspects current implementation + `/ui-reference/`, checks Technology Radar, preserves current capabilities, runs canonical checks and reports deviations. Every generated Codex prompt that touches `site/` MUST inline the hard dashboard/tracking/navigation/content/Studio/SVG/responsive acceptance gates; merely saying “follow Sources” is insufficient. Inspect rendered HTML after checks; passing build/tests alone is not completion.

## Evidence/mastery
Never invent metrics, tests, benchmarks, AI evals or mastery. Use L1 Explain, L2 Implement, L3 Operate, L4 Decide, L5 Lead; mastery requires evidence. Status never locks future sessions.
