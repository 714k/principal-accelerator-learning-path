Subtema 7. Ownership y evolución de estándares

Síntesis en 30 segundos

  1. Ownership identifica quién mantiene el contrato.
  2. Una excepción necesita alcance, responsable y revisión.
  3. Una migración protege los consumidores durante un cambio.

El objetivo es reconocer propietarios, gestionar excepciones y justificar el orden de una migración.

Conceptos del subtema 7

Ownership:

Responsabilidad identificable de mantener y revisar un componente.

Ejemplo: el equipo que publica una biblioteca revisa cambios que afectan a sus tres consumidores.

Excepción documentada:

Desviación acotada y revisable de una regla general.

Ejemplo: una aplicación antigua mantiene un import privado con fecha de revisión y responsable.

Migración:

Transición planificada de productores y consumidores.

Ejemplo: un paquete ofrece exports públicos antes de bloquear los imports internos.

Decisión de arquitectura:

Selección documentada de alternativa, contexto y consecuencias.

Ejemplo: el equipo aprueba exigir imports públicos y registra el coste de migrar consumidores.

Cómo funciona la migración

Primero se detectan importaciones internas. Después la biblioteca ofrece exports compatibles, los consumidores migran y el gate empieza a rechazar nuevos accesos internos.

  1. Inventariar consumidores afectados.
  2. Publicar un contrato de entrada compatible.
  3. Migrar consumidores y comprobar comportamiento.
  4. Activar el gate y acotar excepciones existentes.

El esquema muestra las dependencias permitidas: los consumidores se conectan mediante la API pública, no por archivos internos.

Ejercicio del subtema 7

Una aplicación heredada no puede migrar este mes. Define una excepción verificable.

Mostrar solución razonada

Registrar alcance exacto del import, motivo, responsable, fecha de revisión y gate que rechaza otras excepciones nuevas.

Tarjetas de estudio del subtema 7

¿En qué se diferencia ownership de una excepción?

Ownership asigna responsabilidad; una excepción autoriza temporalmente un desvío con límites y revisión.

Visual Learning Studio del subtema 7

Predice: ¿qué ocurre si el gate se activa antes de publicar exports públicos?

Revelar mecanismo y respuesta

Los consumidores aún dependientes de rutas antiguas pueden fallar. Primero se habilita el contrato nuevo y se coordina la migración; después se activa el gate.

Recursos del subtema 7

  • GitHub: propietarios de código — revisar alcance y límites de CODEOWNERS.
  • npm: entradas públicas de un paquete — estudiar cómo definir exports.

Comprueba lo aprendido

¿Por qué una política de imports no demuestra por sí sola la migración?

Respuesta: la política puede estar escrita sin que todos los consumidores utilicen la API pública; deben inspeccionarse imports y ejecutar pruebas.
